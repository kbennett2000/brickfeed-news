# ADR-0005: Static cover-page render

## Status
Accepted

## Context
ADR-0001 (#1 static-site + git-as-database: "the deploy artifact is rendered HTML") named
the render step but deferred it behind the backend slices. Slices 1–6 built ingestion →
generation → images → durable storage → the category/caption contract, ending at a
newest-first `published.json` (`ManifestRecord[]`) that `publish.ts` explicitly calls "the
seam the future render slice consumes." This is the first UI slice: turn `published.json`
into a static, browser-openable newspaper cover page (+ per-section pages) matching the
`design_handoff_brickfeed/` mockup. Scope ends at static HTML openable locally — no deploy,
no Vercel wiring (that is the next slice).

## Decision

1. **Hand-rolled string templates, no framework, no new dependency.** The design handoff
   ships as a proprietary "Design Component" DSL compiled to React (reference-only). We
   recreate it in the project's own idiom: plain template literals in `src/render/`,
   consistent with the minimal-deps stack (only `fast-xml-parser` at runtime). Adding a
   templating engine or a meta-framework would be disproportionate for a static page.

2. **Pure core + thin CLI, injected clock.** `renderSite(records, { now, secondaryStoryCount })`
   is a pure, total function — records in, a `path → contents` map out, no filesystem and no
   wall clock of its own. `src/render-cli.ts` (`npm run render`) does the IO and passes a
   real `now`; tests pass a fixed one. This mirrors the DI pattern used across the codebase
   and makes the entire page assertable as strings.

3. **`published.json` is the only input seam.** The renderer consumes whole
   `ManifestRecord`s and maps them to display fields, deriving what the design's richer Story
   model needs but our records don't carry: the kicker is the `category`; the byline is a
   decorative `By the {Category} Desk` (the real attribution is the outbound link); "ago" is
   relative time from `firstSeen` vs the injected clock. `imagePrompt`/`wrappedPrompt` and
   the raw feed `title` are never surfaced. The card/headline links out to the source `url`
   (`target="_blank"`), and the "/ BRICKFEED STUDIO" credit is appended render-side.

4. **Per-section static pages, no client JS.** The nav is generated by mapping over
   `CATEGORIES` (src/category.ts — single source of truth), and each section is a real static
   page (`world.html`, …) filtered by category, so navigation works without JavaScript.

5. **Hero + overflow scope for the home page.** Masthead + nav + a large lead + a secondary
   rail of N (config `render.secondaryStoryCount`) + an "Across the Brickyard" card grid for
   the remaining records + footer. The design's feature / "Most Bricked" / Opinion-strip
   sections are deferred (they need editorial hand-picking and copy we don't generate) —
   noted as a follow-on, not built.

6. **Fonts via Google Fonts `<link>`**, exactly as the design prototype, with the
   Georgia/serif fallback for offline. Self-hosting is a possible later fidelity/privacy
   upgrade, not required now.

7. **Chrome is committed source; the rendered site is a build artifact.** The stylesheet
   lives as a string in `src/render/styles.ts` (committed, travels with the repo, covered by
   the "lego" grep of `src/**`). The output dir `site/` is gitignored — generated pages are
   derived output, and how they are served is the next (deploy) slice's decision. This keeps
   the repo text-only without committing generated HTML prematurely.

8. **Robust + never-crash.** Empty/missing `published.json` renders a valid empty-state page;
   a record missing an optional field degrades (e.g. no `imageUrl` → the studded placeholder
   frame, never a publisher's photo). All record text is HTML/attribute-escaped.

## Amendment (2026-07-10)
The masthead + footer tagline described by this ADR (the Latin `TOTVS MVNDVS EX LATERIBVS`,
with the English tagline removed) was reverted. The current render code shows the
plain-English tagline **`All the stories, brick by brick`** in both the masthead and footer,
and the three decorative (hrefless) footer columns were dropped, leaving only the live
"Sections" column. This was a chrome/copy change only — the render architecture in the
Decision section is unchanged. See branch `chore/footer-tagline-and-dead-links`.

## Consequences
- Re-rendering is cheap and idempotent: pure records-in/files-out, safe to run every cycle.
- The legal surface stays minimal: the wordmark is always "brickfeed", only our generated
  art (or a placeholder) is shown, every story links to its source, and the render module +
  output are covered by the `grep -rin lego` gate.
- Deviation from the mockup: the home page ships Hero + overflow only; the
  feature/Most-Bricked/Opinion sections and self-hosted fonts remain as follow-ons.
- Deploy/Vercel wiring is intentionally out of scope; `site/` is produced locally and left
  uncommitted for the deploy slice to pick up.
